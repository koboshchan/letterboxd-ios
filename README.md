
## Sign-in status
Sign-in is required: the app shows nothing but a sign-in screen until the server has validated a session in the current launch (no guest, demo or sample-data mode; a stored Keychain session is never trusted before validation, and offline launches show a retry screen). Sign-out immediately returns to that screen. Implemented but NOT verified end to end. Sign-in opens the site's own sign-in page (it may show a Cloudflare check, which is never bypassed). It is the site's own page in a non-persistent WKWebView (the app does not read or store the password and never fakes the CSRF value or Turnstile token). "Done" collects cookies, keeps only those that apply to https://letterboxd.com, and saves them to the Keychain only after the server confirms the account on the homepage (`person.username` / `person.loggedIn` assignments, recorded fixture). Requests use only an in-memory, server-validated session; ordinary data requests carry no credentials until the server has validated the session. The one exception is the validation request itself: at launch, restore sends the stored cookies to the letterboxd.com homepage to re-confirm the account, and if that fails nothing authenticated is used. Authenticated requests never follow redirects (tested on macOS with a real URLSession against a loopback HTTP server for 301/302/303/307/308, with a positive guest control and a policy-disabled negative control; that harness is plain HTTP on loopback with the site-host check substituted, not TLS to letterboxd.com, and the Linux run skips it), and caches are partitioned by an auth generation that changes on sign-in, sign-out and restore. Nobody has completed a real signed-in run in this app yet. Watchlist and list writes are unsupported.
